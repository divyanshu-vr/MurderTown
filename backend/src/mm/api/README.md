# mm.api: the HTTP and WebSocket API

Owns how Spectators and the Host reach games over the network.

**May import:** every layer below it.

**Entry points**
- `app.py`: `create_app(settings, brains_for, providers)` wires the store, the bus and live games together and runs migrations at startup. It refuses to start without a Host token (`MM_HOST_TOKEN`). Each game is played as its lineup says, on the providers the settings reach (`Settings.providers()`).
- `routes.py`: who may see what. A request carrying the Host token (header `X-Host-Token`) has full scope; one carrying none has public scope, and a wrong token is refused (401) rather than given less. `scope_of` decides it and `host_only` guards everything only the Host may do: start a game (`POST /games`, rate-limited to `MM_NEW_GAMES_PER_HOUR`, 429 past it; a game given no seed is dealt a random one), control one (`POST /games/{id}/pause|step|resume`, 409 for a control the game does not allow now; its summary lists those it does), and look inside one: `/games/{id}/residents/{name}/mind?at=N` (one Resident's mind as of event `N`), `/games/{id}/events/{seq}/explain` (the model attempts behind the decision that caused an event), `/games/{id}/cost` (each Resident's and the narrator's model calls, and their total), `/games/{id}/model-calls?resident=R&after=dN&limit=L` (the game's model calls without their words, in the order the decisions were asked, every attempt at the `L` decisions after `dN`, so a page never splits a decision; while a game plays, decisions asked at once can still add attempts behind a page already read, so its whole list is read once it has ended), `/games/{id}/model-calls/{decision}/{attempt}` (one call whole: prompt, answer and any problem with it) and `/games/{id}/review` (the post-game review of the events stored so far: `mm.review`). Everyone may list games (`GET /games`, newest first) and read one at a glance (`GET /games/{id}`: status, Day, Phase, winner; its cost and the controls it allows only for the Host), page its events (`GET /games/{id}/events?after=N&limit=L`, public scope filtered in SQL so pages stay full), follow it on `/ws/games/{id}?after=N`, which sends the backlog after `N` and then every new event until the game ends or is aborted, and read what the setup form may offer (`/setup-choices`). A browser cannot put a header on a socket, so a full-scope socket asks for `?scope=full` and sends the Host token as its first message; a wrong one is closed with code 4401. Sequence numbers and decision ids keep their gaps in public scope: they count what the town did not see, which tells it no more than its deaths and rules do. Health (`/healthz`) and readiness (`/readyz`) checks.
- `rate_limit.py`: `RateLimit`, a sliding window over what the Host may do only so often. A turn is taken before anything is awaited, so requests sent at once cannot all slip through, and given back if the game is refused.
- `live_games.py`: `LiveGames` runs each game as a background task, storing every event before publishing it and every model call before the event its decision causes. At start-up it resumes every game left running (with `MM_RESUME_ON_BOOT=false` it only lists them in the log), replaying it over its stored events and model calls; a replay that does not reproduce the stored log is aborted right after it and marked `failed`. On shutdown it halts every game before its next decision and waits up to `MM_SHUTDOWN_GRACE_SECONDS` for decisions already asked, so their calls are kept. A game whose model gave no answer is marked `aborted`; one that crashed is marked `failed`, and its log still ends with an abort so Spectators see it stop. `BrainsFor(config, record, recorded)` chooses the decision sources and hands Agents the recorder and, for a resumed game, the calls it had recorded; `lineup_on(providers)` is the usual one. `start` refuses a lineup that cannot be played (the route answers 422) before anything is stored. `control` pauses a game before its next batch of decisions, steps a paused one by one batch, or resumes it; a paused game's status is stored, so it is still paused after a restart.
- `protocol.py`: the protocol as one JSON Schema document, from which the frontend's types are generated.
- `settings.py`: `MM_*` environment settings.

**Why it is shaped this way:** routes only translate between HTTP and the layers below, so every rule stays testable without a network.
