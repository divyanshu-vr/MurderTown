# mm.orchestrator: running a game

Owns the order of play: casting, then each Day's Phases, checking for a winner after every Phase.

**May import:** `mm.agents`, `mm.observability`, `mm.engine`.

**Entry points**
- `game.py`: `play_game(config, brain_for, *, observers, clock, game_id, replay)` plays a whole game and returns its events and final state. The clock only times the Open floor; tests pass a fake one. `Game.decide` asks one Resident and checks the answer is legal; `Game.decide_all` asks several at once and returns answers in the order asked; it stamps every decision id before any answer can arrive, so ids never depend on timing. `Game.decided` says whether a side has already won; a Phase checks it after any death, so nobody acts once the game is over. Every decision causes at least one event, appended with `cause=` so it names the decision; a Sheriff holding fire, for instance, causes a `SheriffHeldFire` that only Spectators perceive. A fallback is reported once, beside the first event its decision caused. When a decision fails (`ModelFailureError`), the game appends `GameAborted`, naming that decision, and stops; a crash also appends one, naming nothing and saying only that the game hit an internal error, before the error goes on to the caller; when several decisions asked at once fail, the first in the order asked is the one reported, so the same failures always end the game the same way.
- Tracing and logs: a game runs `in_game` (its session) with its id bound to every log line; each decision starts its own trace, `decision.<kind>`, and binds the deciding Resident.
- `log.py`: the append-only `EventLog`. Appending applies the event to the true state, stamps it, then tells each observer (storage, the live bus) in order. `unlogged` stamps something already heard but not appended yet. With `replay`, the events a stopped game had stored, it checks each event it makes again against the stored one (`ReplayDivergedError` if they differ) and tells no observer until it has caught up.
- `phases/`: one module per Phase. Each builds requests, collects decisions, calls the engine's rules and appends events, naming the decision that caused each one. Dawn and the Vote end with `reflection.reflect`, in which every living Resident with news writes a reflection. The Sheriff's choice is one function, `showdown.sheriff_decides`, which the Showdown or Night calls depending on the configuration. Night runs the Den one Murderer at a time, then asks for every kill vote, protection and investigation at once; Dawn announces the result, then the narrator recaps. Dusk runs its Conversations in waves: each round asks the next speaker of every unfinished Conversation at once, and a wave's messages are held back (`decide_all(..., pending)` lets the speakers hear them) and appended Conversation by Conversation when the wave ends.
- `narrator.py`: `NARRATOR`, the storyteller. It borrows a Resident record only so every decision source can give it a Brain, and perceives only public events.

**Resuming a game:** `play_game(..., replay=stored_events)` plays the game again from its seed. Everything a game does is seeded or decided, so with the same decisions it makes the same events: each Brain is asked again in the same order (so scripted bots' own draws stay in step), and LLM Agents answer from the calls they had recorded. The one exception is the clock, which ends an Open floor that runs out of time, so that is recorded as `OpenFloorTimedOut` and a replay follows the record (`Game.out_of_time`); a resumed Open floor gets its full time limit again. Setting `halt` stops a game before its next decision with `GameHaltedError`, after the decisions already asked finish, so it can resume later.

**Why it is shaped this way:** Phases stay thin because the rules live in the engine; concurrent answers are appended in a fixed order (seat order; at Night by role; at Dusk, each wave's messages Conversation by Conversation) so the log is the same however fast each Brain answers.
